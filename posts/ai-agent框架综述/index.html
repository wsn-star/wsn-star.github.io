众仙摆阵：AI Agent 框架全景综述

2026年09月18日 约 4 分钟 无名散修
  • AI
  • Agent
  • 框架
  • LangGraph
  • CrewAI

昔者各据一隅,今则百器争鸣。铸造术之盛,莫过于此。

一、时代背景：框架们「成年」了

2023 年,"做一个 AI agent"意味着用 while 循环包一层 GPT-4 调工具。到 2026 年,框架已经追上真实生产 agent 系统的复杂度。最关键的转折:

  • 基础实验室亲自下场:OpenAI、Google、Microsoft 都发布了第一方 agent 框架,结束了独立框架"一家独大"的局面。
  • 两个标志性事件: 1. OpenAI Swarm 退役,被正式开源的 OpenAI Agents SDK 取代; 2. Anthropic 把 Claude Code SDK 更名为 Claude Agent SDK,宣告它不再是"仅编码"工具。
  • LangGraph 0.3 把 中断与人工介入(human-in-the-loop) 提升为一等公民。

二、头部框架逐项拆解

2.1 LangGraph(STateful 图式工作流)

  • 定位:有状态、图式控制流的 agent 工作流,默认选型用于复杂 Python 流程。
  • 形态:把 agent 编排成一张图,节点 = 步骤,边 = 转移,天然支持分支/循环/并行。
  • 硬实力:内置 checkpointing(回滚/恢复)、模型无关、34.5M 月下载量,被 Klarna、Replit、Elastic 采用。
  • 代价:学习曲线最陡(1~2 周),上手不如脚本派快。

2.2 CrewAI(角色制多智能体团队)

  • 定位:基于角色的多 agent 协作(" crew ",团队模式),约 20 行 Python 出一个可用原型。
  • 演进到 v1.12:agent skills、原生 OpenAI 兼容供应商(OpenRouter/DeepSeek/Ollama/vLLM/Cerebras/Dashscope)、Qdrant Edge 记忆后端、分层记忆隔离。
  • 数据:52.8K stars / 5.2M 下载,学习约 3~5 天,靠速度与直观取胜。

2.3 OpenAI Agents SDK(极简)

  • 定位:官方 SDK,在 OpenAI 技术栈上的最小抽象。
  • 新特性强大:通过 LiteLLM 实现供应商无关、支持 100+ 模型;10.3M 下载,是团队已扎根 OpenAI 生态时最快开跑的多 agent 路径。
  • 代价:想换到非 OpenAI 生态时有一定锁定。

2.4 AutoGen / AG2 / Microsoft Agent Framework

  • AutoGen 0.4:一次 actor-model 重写,转向事件驱动架构;AG2 是 ground-up 重新设计的 Beta,强调流式与事件驱动。
  • Microsoft 走双轨(AutoGen 0.4 + Semantic Kernel Agent Framework),一个偏研究探索、一个偏企业落地。

2.5 其它值得点名

  • Claude Agent SDK:Anthropic 把编码工具身份扩大为通用 agent 平台,背靠其强大的 harness(见 Harness 篇)。
  • Google ADK(Agent Development Kit):google 第一方,与 Gemini 深度整合。
  • LlamaIndex / Pydantic AI / Vercel AI SDK:分别主打数据编排、类型安全、前端集成,各据一方。
  • Mastra / Cargo AI / AWS Strands Agents 等新兴势力,AWS 亦在 agent 编排领域布局。

三、选型决策矩阵(可操作)

这是本综述的核心实用产出——按你的场景对号入座:

你的需求 首选框架 理由
有状态、复杂分支/循环、可回滚 LangGraph checkpointing + 图控制流
多角色协作、快速原型 CrewAI role-based 团队,20 行出活
已在 OpenAI 栈、要最小抽象 OpenAI Agents SDK 官方、快、LiteLLM 多模型
研究型事件流 agent AG2(AutoGen) 事件驱动重设计
企业级 + 微软生态 Semantic Kernel Agent FW 双轨里的落地轨
通用自治能力 + 强悍 harness Claude Agent SDK Anthropic 全栈
数据密集、检索驱动 LlamaIndex / ADS 数据编排优

四、2026 年的三大共性趋势

  1. 可观测性成为标配:agent 不再" 黑盒",trace、中间状态、人工介入点都是框架内建能力(Ry Walker 对 13 个框架的横向评测里,observability 是核心维度)。
  2. 记忆与上下文工程化:Qdrant Edge 记忆、分层隔离、记忆后端化——长期记忆不再是玩具。
  3. 模型无关 vs 生态绑定之争:一边是 LiteLLM/OpenRouter 式的" 什么模型都能接",一边是官方 SDK 的深度锁定,选型时要想清楚自己在哪边。

五、避坑与建议

  1. 别让框架决定业务。先用手画出你 agent 的流程图(状态、分支、人工卡点 To be selected),再挑能原生表达它的框架。
  2. 警惕"Hype 改命":LangGraph 学习曲线背后的价值是" 有状态、可回滚",如果你只需一个简单循环,OpenAI SDK / CrewAI 更快,别为过度工程买单。
  3. 一定要有人工介入点:把 human-in-the-loop(如 LangGraph 的 interrupt)设计成默认,而不是事后补丁——这关乎可控性。
  4. 企业选型看可观测性与安全:选带好 trace 与记忆隔离的,别选最炫的。

六、结语

2026 年的 agent 框架,已从" 证明你也能写个 agent"的炫技阶段,进入" 管得住、看得见、能回滚、敢上生产"的工程阶段。真正的选型智慧,不是追最火的名字,而是:让框架匹配你的状态拓扑,让你永远握有人工介入的缰绳。
