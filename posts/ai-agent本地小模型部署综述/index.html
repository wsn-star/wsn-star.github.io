AI Agent 本地部署小模型综述

2026年09月18日 约 4 分钟 无名散修

一、为什么「小模型本地部署」突然重要

两年前的共识是「能力在云端」,但 2026 年的格局已经反转:

  1. 隐私与合规:数据不出门成为硬约束——医疗、政务、企业知识库,明文数据不能上云。
  2. 延迟与成本:端侧推理零网络延迟、零按 token 计费,对 Agent 的长任务循环尤其重要。
  3. 模型变小但变强:蒸馏与量化让 1.5B~9B 的小语言模型(SLM)在多数任务上"够用"——这正是 Agent 里调用最频繁的那一层。

二、硬事实:量化革命改变了什么

一个常被引用的数字对比:

一个 70 亿参数模型,FP32 需要约 28GB 显存;4-bit 量化后降到 不足 4GB,质量损失在多数任务上几乎不可感知。

这让本地推理从「企业 GPU 才能玩」变成「M 系列 MacBook、游戏级 RTX、甚至高内存纯 CPU 机器都能跑」。量化(特别是 GGUF 格式的 Q4_K_M 级别)是这一切的基石。

三、运行时全景:六大选择

2026 年边缘 LLM 运行时格局(据 Edge LLM Runtime Stack 与 Building Language AI 的梳理):

运行时 硬件倾向 定位 适用场景
llama.cpp 通用,CPU 优先 最可移植的 C/C++ 运行时,GGUF 格式 能跑就行,兼容性第一
Ollama 通用 llama.cpp 的便捷封装 + HTTP API 原型与开发者工作流的事实标准
MLX Apple Silicon 为统一内存专门打造 M 系列 Mac,14B 以下模型比 llama.cpp 快 20%~87%
ExecuTorch 移动端 PyTorch → 手机的运行时 Android/iOS 端上 Agent
WebLLM 浏览器 WebGPU 在浏览器里推理 无安装、纯网页的 Agent 界面
Qualcomm AI Hub Snapdragon NPU 高通 NPU 工具链 骁龙设备的端侧 Agent

关键提醒:量化格式不能随便跨运行时迁移。GGUF 在 CPU/Jetson/Apple Silicon 间可移植,但 NVFP4 这类 Blackwell 专用格式就不会在 Orin 上跑。选型时要先定硬件,再定格式。

四、模型侧的三板斧

从系统综述(On-device LLMs: a survey of model compression and system optimization)看,本地小模型的能力来自三条技术线:

  1. 量化(Quantization):4-bit/2-bit 权重量化,GGUF/QAT 等,是"省显存"的第一功臣。
  2. 蒸馏(Distillation):大模型把能力压缩进小参数模型,让 SLM"继承"大模型的行为。
  3. 剪枝与低秩适配(LoRA):进一步瘦身 + 低成本微调,让模型贴合你的领域。

这三者往往组合使用,而非单选。

五、硬件边界:CPU、GPU、NPU 怎么选

  • CPU 为主:llama.cpp + GGUF,高内存即可跑 7B~14B,速度 5~20 tok/s,够日常问答与知识库检索。
  • GPU 加速:游戏级显卡即可流畅跑 14B 甚至 32B 量化模型,是「本地 Agent 主力机」的首选。
  • NPU 崛起:2026 年 Windows 的 ONNX Runtime + Qualcomm QNN 让 NPU 开发走上正轨;NPU 擅长矩阵运算,能效比高,但生态与格式仍在收敛。
  • Apple Silicon:统一内存架构 + MLX,是目前「端侧体验最好」的组合。

六、给 Agent 落地者的路线图

  1. 先定硬件边界,再选运行时:Apple Silicon 上 MLX、通用桌面 Ollama/llama.cpp、手机 ExecuTorch、浏览器 WebLLM。
  2. 从 7B 级量化模型起步(GGUF Q4_K_M),验证任务质量;不够再升 14B,别一上来就冲大。
  3. 嵌入模型与生成模型分开:嵌入用更轻的(如 nomic-embed-text),生成用稍大的,性价比最优。
  4. 与本地知识库/RAG 组合(见《AI 本地个人知识库建设》):小模型 + 检索,是「本地 Agent」最务实的组合。
  5. 评估闭环不可省:本地模型差距用你的真实任务集验证,别用榜单结论代替。

七、结语

2026 年,「把 Agent 跑在本地」不再是妥协,而是一种架构选择:隐私、成本、延迟、可控,全都要回来了。量化与蒸馏把大模型的能力压缩进更小的参数规模,而你的任务,是选对那套适合自己硬件的组合——不是越大越好,而是在你能掌控的硬件上,跑出可信、可验证的结果。
