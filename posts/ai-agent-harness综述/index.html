AI Agent 的 Harness 工程综述

2026年09月18日 约 4 分钟 无名散修

一、什么是一个「Harness」

2026 年最不该被忽视的一个认知转变:

Agent = 模型 + Harness。

Harness(又称" 机架 / 宿主 / 运行时")是把 LLM 与外部世界耦合起来的那套运行时——agent 循环、工具、上下文管理、安全控制、编排、扩展接口,统统属于 harness,而不是模型本身。

一篇对 11 个生产级编码 harness 的源码解剖研究(Harness Engineering: Anatomy... of Coding Agents)给出了精确的定义:

An agent is a model plus a harness: the runtime that couples an LLM to the world through a loop, tools, context management, safety controls, orchestration, and extension surfaces.

二、为什么突然被重视

两个残酷的事实,把 Harness 从配角推向舞台中央:

  1. 模型已「收敛」。2023—2026 年间,前沿模型之间的差距迅速缩小。对多数生产任务,换一家顶级模型,结果往往变化不大;决定胜负的,在下一层——你怎么调用它、喂什么上下文、给什么工具。

  2. 「98% 的问题在模型之下」。BeConfident Labs 的综述标题直白地点出:agent 的质量落在模型之下——在循环、上下文引擎、工具面、安全栈与评估器里,而不是模型本身。

  3. 硬数据:多篇研究指出,任务变长变复杂时,仅靠重设计 harness(模型保持不变),可靠性就能获得数量级的提升(order-of-magnitude reliability gains)。

三、Harness 的四大组成

综合几篇 2026 年 survey,Harness 工程的核心部件可归为四层:

3.1 循环与上下文引擎

  • agent 循环:模型怎么被反复调用、何时停、如何从工具结果继续。
  • 上下文引擎(context engine):决定" 喂什么给模型"。长上下文、择优抽取、上下文压缩,避免" 上下文稀释"。
  • 这是" 98%"里最能拉开差距的一环——给多、给乱,不如给对。

3.2 工具面(tool surface)

  • 模型能调用哪些工具、每个工具如何定义/约束、工具返回如何被消化。
  • Claude Code、Codex CLI、Gemini CLI 等 11 个编码 harness 的解剖研究,把" 工具面"作为影响成败的核心维度之一。

3.3 安全与确认控制(safety controls)

  • 不是模型的 safety,而是运行时对危险动作的拦截与确认。
  • 人工介入点、权限边界、破坏性操作确认——这是 agent 能" 上生产"而与" 玩具"分开的关键分界线。

3.4 编排与扩展(orchestration & extension)

  • 多 agent 如何协作、子代理如何并行、可插拔扩展接口(MCP 等)。
  • Cursor 的" 自驾驶代码库"研究,正是一个能编排上千个 agent 的 harness——这是 Orchestration 的极端形态。

四、一个兴起的新范式:代码即 Harness

一篇 2026 论文提出 Code as Agent Harness,把代码本身当作 agent 的运行底座:

  • 代码不再只是" 目标输出",而是agent 推理、行动、环境建模与基于执行的验证的操作性基质。
  • agent 通过生成/执行代码来" 思考和验证",用可执行的东西代替纯粹的文本猜测。
  • 这为" 可执行、可验证、有状态"的 agent 系统提供了统一视角。

五、研究如何落地:GROOM 之类

BeConfident Labs 在 survey 中提出并开源 GROOM,一个" 自维护的知识 harness"。它展示了 Harness 理念的落地:把长期记忆、上下文引擎、工具面与评估器做成一个能自我维护的系统,而非散装拼装。

六、给从业者的判断框架

  1. 换模型前,先看 harness。如果你的 agent 效果不好,先排查上下文喂得对不对、工具面全不全、循环停得合理与否,再决定是否花大价钱换模型。
  2. 把安全控制做成默认。危险操作确认、权限边界,是 harness 设计的" 地基",不是后补的补丁。
  3. 关注可观测性。Harness 的价值在于"看得见"——中间状态、每一步的决策,都应有 trace。
  4. 用评估器做闭环。harness 里应有"评估"部件,让 agent 自己验证结果(如跑测试),而不是靠想象。

七、结语

如果说 2025 年是" 模型之年",那么 2026 年就是 "Harness 之年"。当模型越来越像、越来越强,真正的护城河与决胜点,转向了那层看不见的运行时——谁能让模型更可靠、更安全、更可控地干活,谁就赢。
